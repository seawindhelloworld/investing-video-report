# 每日报告模板

## 写作前的覆盖门

在起草正文前，先从 `video-analysis.json` 和转录建立章节覆盖清单。每个章节至少拆成：

- 作者转述的事件或数据；
- 作者自己的解释、判断和预测；
- 作者给出的依据；
- 限定词、反例、未决问题和行动；
- “科技五大新闻”中的五条新闻，以及其他不属于主观点但具有实质信息的内容。

正文必须覆盖每个实质性子主题，但“覆盖”分为默认可见的理解层与同页折叠的审计层。不得另做一个与默认报告割裂的“详细版”附件；完整依据、限定、原话和时间戳应保留在同一份 `report.md` / `index.html` 的 `<details class="report-detail">` 中，并继续进入结构化产物。

完整覆盖不等于默认全部展开。默认页面采用“先图后文、先结论后证据”：一页结论图 → 第一层主题简报 → 第二层证据增量矩阵 → 第三层决策简报 → 同页折叠依据与信源。逐条观点、完整证据与全部信源同时保留在 `report-data.json` 和 `citations.json`。

“紧凑”不是丢失原意。每个主要主题的默认可见区应让读者无需打开结构化附件就能理解一句结论、至多三项关键依据或分歧、核心限定和下一验证；背景、完整推理链、较长原话和审计定位在同页按需展开。不设按播放时长推导的字数或篇幅配额。

## 写作前的轻量编辑规划

在同一次报告生成运行、同一上下文中先确定：

- 一个核心命题和 3—5 条读者要点；
- 主要主题、次要主题及其决策影响，不以讲述时长排序；
- 每个主要主题稳定的 `claim ID`；
- 默认可见的信息增量与折叠保存的审计内容；
- 能真实表达比较、因果、条件或验证路径的可视化；没有合适关系时使用短句或小表。

该规划不另起模型调用、子任务或文件。三个层级分别使用相同 claim ID 的 `topic-brief`、`evidence-delta` 和 `decision-brief`；第二层只写相对第一层的证据增量，第三层只写相对前两层的决策增量。

对字幕汉字不少于 2500 且已经形成研究主题的长报告，草稿门禁要求：claim 数量与 research topic 数量一致；每个默认可见 claim 组件不超过约 260 个汉字；每个 claim 至少有两个默认关闭的同页 `report-detail`；第一层默认可见汉字不超过报告字幕的 42%；三层默认可见总量不超过 `max(3200, 1200 + 750 × research topic 数量)`。这些限制只计算默认展开内容，折叠审计依据不计入压缩量。

商业广告、产品推广、订阅引导和销售话术不属于需要覆盖的实质性内容，无论出现在片头、中段或片尾，都不得进入观点、最终 Markdown 或 HTML。片头/片尾的明确广告可登记排除时间范围；高确定性的中段商业口播登记在 `non_reportable_ranges`，原文仍保留在字幕依据和筛选视图中，但在观点、研究与成稿时略去。无法确定时保留内容，不做大段省略。片尾确有五条科技新闻时，固定使用章节标题 `科技五大新闻`，不得把前置广告写入该章或计入结构化章节起始时间；最终页面不显示本章的视频时间。

报告不得使用视频封面，不设置独立的“视频信息”章节，也不在标题下加入“完整保留 N 分钟视频”“本报告覆盖多少内容”等宣传式开场。来源、作者和发布时间保留在 front matter、HTML 顶部元数据和时间戳链接中即可。

## 三层报告结构

- 第一层“视频作者观点”：使用显式标题 `第一部分｜视频 / 作者内容`。开头一次性声明来源边界，之后采用内容直述，完整呈现“数据/依据 → 如何推理 → 判断与结论 → 限定与行动”，不反复使用“视频称”“作者表示”等主持式归因。
- 第一层内再区分“事件 / 数据 / 管理层口径”和“讲者个人判断”。凡讲者明确给出的个人研判、持仓或交易行动，使用醒目的 `speaker-opinion-marker` 卡片，显示“报告标注 · 视频内个人判断”和具体姓名。该卡片仍属于视频内容，不能使用外部研判或 Agent 判断样式。
- 第二层“外部证据研判”：逐条或按主题展示支持证据、反方证据、适用范围、前提差异和不确定性。
- 第三层“Agent 综合判断”：在前两层完成后，给出跨主题结论、置信度、适用期限、已计价判断、成立条件、量化反证、下行机制、观察姿态和缺失证据。
- 默认报告顺序必须是：视频正文 → 外部研判总览与主题卡 → Agent 综合判断 → 信源 → 方法与限制，不得把 Agent 判断混入视频正文。
- 每一节先给一句章节导语，再展开细节；不能用导语替代细节。
- 主题可按实际内容自然归类为概览、宏观/政策与地缘事件、行业、具体公司、科技快讯等；只保留实际出现且有信息价值的类别。
- 讲述时长、时间占比和出现顺序只用于定位与覆盖检查，不能决定主题重要性、正文篇幅、外部研究深度或 Agent 判断权重。
- 重要性由核心命题关联度、决策影响、论证密度、风险、证据需求和不确定性决定。短但关键的结论、警告或反例可以重点展开；长篇背景或推广可以简洁处理。
- 第二、三层的主题卡片都应链接回第一层对应章节；卡片不得穿插到第一层正文中。
- 报告免责声明、核查边界、ASR 风险和删减理由必须作为编辑层显式标注；不得与第一层观点正文混写。
- 商业广告与产品推广无论位置都不进入正文或观点；中段原文只保留于字幕依据，不做源内容删除。五条片尾科技新闻固定放入“科技五大新闻”章节，且不在页面显示视频时间。
- 同一信息不得在摘要、正文、图表和后续两层中重复整段出现。第一层保留原意；第二层只补充支持、反方和条件；第三层只给综合取舍、已计价、反证与下一验证。跨层必须复用稳定 claim ID，不能复用完整段落。
- 每个主题默认使用一句结论、一张真正有信息关系的主图或紧凑表、至多三项关键依据/分歧和一个下一验证。讲者判断卡默认呈现忠实的一句话概括；完整原话、背景、推理与限定放入同页折叠区。
- 外部研判默认按主题汇总，不在页面铺开逐条观点长表；Agent 的必填字段使用紧凑网格、定义列表或卡片；长信源组在 HTML 中默认折叠。

## 可视化路由

只使用能够由视频转录、结构化观点或外部研判直接支持的图。优先选择：

- 主题结构图：显示概览、宏观、行业、公司和快讯之间的内容关系，不用面积或宽度暗示重要性；
- 时间戳导航：只在确有助于回溯时显示起止位置，不计算时间占比，也不把时长编码为重要性；
- 正负驱动或论证关系图：显示作者的推理链，而不是装饰；
- 同口径数字对比：财报实际值、预期值、环比或同比；
- 公司/主题条件矩阵：比较不同观点的成立条件；
- 外部研判分布：显示支持、分歧、条件和证据缺口。

图中必须标明“视频所述”或“外部研判”的证据边界，数字不能跨单位共用同一尺度。图表不能替代正文，也不能把推断画成已确认事实。

优先选择真正减少阅读成本的图。若一张图不能表达关系、比较、状态、条件或验证路径，则使用短句或小表，不为“图多”而添加装饰图。
